### 0.1 注册个体工商户主体前，先核对这张执照

| 检查项 | 为什么 | 不合格怎么办 |
|---|---|---|
| 有没有营业执照（校服店实体店一般都有） | 没有执照就没有「商家自营」类目，也没法开微信支付 | 线上办个体户执照（政务服务网，0 元，1–2 天），经营范围勾「服装零售」「互联网销售」 |
| 经营范围里有没有「互联网销售」或「服装零售」 | 小程序类目要和经营范围对得上，审核会看 | 去政务网做经营范围变更（增项通常当场或 1 天） |
| 执照在有效期内、没列入经营异常 | 主体信息会被核验 | 先处理异常名录 |
| 谁做「经营者」 | 注册时要经营者身份证 + 微信扫脸验证 | 用执照上那个人的微信扫，别用别人的 |

### 0.2 微信支付要额外做的事（不阻塞课程，但收款必需）

1. 小程序**微信认证**（个体户 30 元/次，限时价；企业 300 元）。没认证开不了云服务、也上不了架。
2. 申请**微信支付商户号**（免费）：小程序后台 → 微信支付 → 关联商户号，或直接申请新商户号。
3. 商户号资料：营业执照、经营者身份证、**结算账户**——个体工商户可以填经营者本人的银行卡，不强制对公账户。
4. 费率 0.6%，结算 T+1；商户号审核一般 1–3 个工作日。
5. **ICP 备案**：现在新注册的小程序要备案才能发布。个体户备案走的是主体资质，1–2 周，越早提交越好（开发、体验版不受影响）。
6. 商户号下来后，把**商户号 + API 密钥**填进云函数（`cloudfunctions/api/common/` 里我已经留了支付下单的位置，等商户号到了再启用真支付）。

### 0.3 谁当「管理员」：维护的人当管理员，经营者填主体信息

小程序后台有四个角色，别混：

| 角色 | 干什么 | 能不能换 |
|---|---|---|
| **管理员** | 绑微信支付商户号、改核心设置、扫码授权一切敏感操作 | 能换，但要**原管理员扫码**确认（原微信丢了就得走公函 + 法人资料，很麻烦） |
| 运营者 | 发布版本、看数据、处理订单 | 能加能删 |
| 开发者 | 上传代码、真机调试、体验版 | 能加能删 |
| 登录邮箱 + 密码 | 登录后台 | 能改 |

**这个项目的分配（2026-11-20 定）：**

- **管理员 = 你**（长期维护、发版、调云函数的人）。微信必须已实名（绑过银行卡），手机号要长期能用。
- **主体信息里的经营者 / 法定代表人 = 妈妈**（营业执照上那个人）。微信认证那步由她扫脸。
- 注册完把妈妈加成**运营者**：她只需看订单、发货、处理退货，不用碰代码和设置。
- 备案时：**主体负责人 = 妈妈**（广东要求主体负责人必须是法定代表人），**小程序负责人 = 你（= 管理员）**，广东允许小程序负责人不是法人，不用授权书。

> 一个微信号最多当 5 个小程序管理员；管理员微信只要能扫码就一直有效，别用完就换号。

### 0.4 注册时那个「主体验证信息」表单怎么填

| 字段 | 填什么 | 说明 |
|---|---|---|
| 主体验证方式 | **选「法人扫脸」** | 三选一：对公账户打款（要公司对公账户，个体户没有，别选）/ 法人扫脸（经营者本人微信扫码 + 人脸，**最简单**）/ 电子营业执照（得先有电子执照 App，也可以） |
| 开户名称、开户银行、开户银行账号 | 选扫脸就**不用填**（灰着或跳过） | 只有选「对公账户打款」才要，且微信会往该账户打一笔随机小额，你要回来填金额 |
| 联系人姓名 / 身份证号 | **执照上的经营者（妈妈）** | 认证会按这里的身份证核对主体关系；填别人可能被要求补授权书。审核过程会**打电话**核实，所以电话也填她的、并保持畅通 |
| 联系人电话 + 短信验证码 | 妈妈能接的号，点「获取验证码」 | 陌生来电别挂 |
| 联系人座机 | 有座机填完整区号（珠海 `0756-xxxxxxx`）；没有就填手机号 | 要求「完整区号、座机号、分机号」，没有分机可不填 |
| 电子邮箱 | **你注册用的那个（你的）** | 这是**账号邮箱**：登录后台、找回密码、收认证结果都靠它，不是"联系邮箱" |

> 一句话记法：**跟执照、主体、扫脸有关的字段填妈妈；跟登录、账号、代码有关的填你。**

> 走到下一步会收认证费：个体户 30 元/次（限时价），企业 300 元/次。付完等审核，通常 1–3 个工作日。

## 第 2 步：建集合、导数据、传云函数（你来点，我给的清单照抄）

### 2.1 建四个集合

云开发控制台 → 「数据库」→ 新建集合，建这四个，名字一字不差：

| 集合 | 放什么 | 权限选 |
|---|---|---|
| `products` | 商品（价格、库存、图） | **所有用户不可读写** |
| `orders` | 订单 | **所有用户不可读写** |
| `users` | 用户积分/累计消费 | **所有用户不可读写** |
| `admins` | 店长 openid 白名单 | **所有用户不可读写** |

> 四个都选「所有用户不可读写」，因为所有读写都经过云函数，云函数用的是管理员权限。
> 选成「所有人可读」，别人就能直接翻你的订单表和价格表。

### 2.2 导入商品

1. 控制台 → 数据库 → `products` → 「导入」
2. 文件选 `cloudfunctions/seed/products.json`
3. 冲突处理选 **Insert**（或 Upsert），编码 UTF-8
4. 导入完应该有 **8 条**记录，`p1` 价格 128、库存 86

> 这个文件是 `node tools/export-products.js` 生成的，改了 `data.js` 的价就重跑一次再导。

### 2.3 上传云函数

1. 开发者工具左侧文件树，找到 `cloudfunctions/api`
2. **右键 → 「上传并部署：云端安装依赖」**
3. 等它装 `wx-server-sdk`（第一次 1–2 分钟）
4. 看到「上传成功」就行

> 只改 `index.js` 或 `common/*.js` 也要重新上传，云函数不会自动同步。
> 本地改完先跑 `node tools/cloud-test.js`（49 条），过了再传，省得来回试。

### 2.4 把自己设成店长

1. 先在小程序里随便点一下，触发一次 `me` 调用（或在开发者工具「云开发 → 云函数 → api → 测试」里执行 `{"action":"me"}`）

## 常见错与对策

| 现象 | 原因 | 怎么办 |
|---|---|---|
| `errCode: -501000` / `cloud init error` | 环境 ID 没填或填错 | 检查 `cloud.js` 的 `ENV_ID`，和「环境设置」里的 ID 逐字对 |
| `collection not exists` | 集合没建，或名字拼错 | 四个集合名对照上面表格 |
| `permission denied` | 集合权限选成「仅创建者可读写」 | 改成「所有用户不可读写」，读写全走云函数 |
| `Cannot find module 'wx-server-sdk'` | 上传时没选「云端安装依赖」 | 右键重新上传，选带「云端安装依赖」那一项 |
| `只有店长能做这个操作` | `admins` 表里没有你的 openid | 2.4 加一条 |
| 页面价格和云端不一致 | 改了商品价没导 `products` | 重跑 `node tools/export-products.js` 再导入 |
| 真机上积分不涨 | 确认收货那步走的还是本地 store | 第 3 步改完页面才有云端积分 |
| 注册时提示「该邮箱已被占用」 | 之前用这个邮箱开了个头（激活了邮件）但没填完，**未完成注册的账号不会释放邮箱**，30 天超时也不释放 | 别换邮箱先试这个：打开 https://mp.weixin.qq.com → 二维码右上角「使用账号登录」→ 用当时的邮箱 + 密码登录 → 按页面提示接着填（停在「主体信息登记」就直接选 企业→个体工商户）。忘了密码走登录框下「忘记密码」用该邮箱重置。确定不要那个号：先把它注册完成，再「设置 → 账号信息 → 注销账号」，注销后邮箱才释放。嫌麻烦就换一个**从没注册过任何微信产品**的新邮箱 |

## 记下来的决策

- **只做一个云函数 `api`**，用 `action` 分派。理由：部署只要一次右键，少一步错一步；真到大流量再拆。
- **前端只传 productId / size / qty**，价格、运费、折扣、积分全在 `cloudfunctions/api/common/rules.js` 算。
  理由：现在的价格是手机算的，改内存就能白拿。
- **`rules.js` 和 `store.js` 的常量与算法必须一致**，`preview/flow-test.js` 第 13 节专门盯这件事。
- **没填环境 ID 就自动走本地**：网页演示版和「没开通云的同学」都能跑，不会白屏。

## 数据库索引与集合权限（v1.1）

### 集合权限（云开发控制台 → 数据库 → 选集合 → 数据权限）

四个集合全部选 **「所有用户不可读写」**。前端一律走云函数，不让小程序端直接读库。

理由：`products` 里有成本价和库存，`orders` 里有手机号和地址。开「所有人可读」等于把这些公开给任何反编译小程序的人。
「仅创建者可读写」也不行——那会让买家能直接改自己的订单状态。

### 索引（云开发控制台 → 数据库 → 选集合 → 索引管理 → 新建索引）

| 集合 | 索引字段 | 索引类型 | 对应查询 |
| --- | --- | --- | --- |
| `orders` | `openid` 升序 + `createdAt` 降序 | 组合索引 | `listOrders` 买家侧 |
| `orders` | `status` 升序 + `createdAt` 降序 | 组合索引 | `listOrders` 店长侧按状态筛 |
| `orders` | `no` | 唯一索引 | 订单号，防重复落单 |
| `products` | `sales` 降序 | 单字段索引 | 首页「本周精选」 |
| `users` | `openid` | 唯一索引 | 一人一条 |

注意：云开发的唯一索引在插入重复值时会报 `duplicate key`，`service.js` 里已经把这个错翻成
「订单号重复了，再点一次」，不会把英文报错甩给用户。

### 分页

`listOrders` 一次最多 20 条（`PAGE_SIZE = 20`），返回 `hasMore`。
买家侧「我的订单」滑到底自动加载，店长台点「看更早的订单」。
**为什么必须分页**：开学季一天几十单，一次拉全部会让店长台首屏白 2–3 秒。

### 并发

扣库存、扣积分、改订单状态都改成「一条语句带条件」：

- 库存/积分：`incField(coll, id, 'stock', -qty, qty)` → `where(stock >= qty).update({stock: _.inc(-qty)})`，扣不动就说明被别人抢先了
- 状态流转：`cas(coll, id, {status: 'from'}, {status: 'to'})` → 只有当前还是 `from` 才改

这样两个人同时点「确认收货」只会有一次生效，第二个人看到「这单刚被确认过」。
**注意**：这套办法能扛住「同一单同一动作的重复点击」，但扛不住高并发下的跨集合事务
（比如同时退积分 + 改订单，中间失败会留下一半）。真要上量，得换云开发的事务 API 或自建服务。
现在这个量级（一天几十单）够用，代价写在 `docs/决策记录.md` D014。

## 微信支付（v1.4 已接，等你填环境变量）

代码在 `cloudfunctions/api/common/wxpay.js`（v3 JSAPI 下单 / 主动查单 / 回调解密），
业务在 `service.js` 的 `createPayment` / `confirmPay` / `markPaid`。
**私钥和密钥只从云函数环境变量读，绝不写进仓库。**

### 1. 商户平台里先准备四样

| 东西 | 在哪拿 | 填到哪 |
|---|---|---|
| 商户号 `MCH_ID` | 账户中心 → 商户信息 | 环境变量 `MCH_ID` |
| 证书序列号 `MCH_SERIAL_NO` | 账户中心 → API安全 → 商户API证书 → 详情（32 位十六进制） | 环境变量 `MCH_SERIAL_NO` |
| 商户私钥 `apiclient_key.pem` | 申请证书时下载的压缩包里的 `apiclient_key.pem`，用记事本打开整段复制 | 环境变量 `MCH_PRIVATE_KEY`（也接受该文件的 base64） |
| APIv3 密钥 `API_V3_KEY` | 账户中心 → API安全 → **页面最下方「解密回调」** → 设置（32 位，只显示一次） | 环境变量 `API_V3_KEY` |

可选：

- `PAY_APPID`：默认已经是 `wx37e1073cc15df404`，不用填
- `PAY_NOTIFY_URL`：有公网 HTTP 访问服务时填回调地址；不填就走「主动查单」那条路（见决策 D017）

### 2. 填进云函数（两种办法，推荐 ②）

**① 环境变量**：云开发控制台 → 云函数 → `api` → 「版本与配置」→「配置」→ 环境变量。
注意：微信云开发控制台 2.0 的部分版本里这一块是**只读**的，找不到「编辑」就换 ②。

**② 写本地文件（本项目默认，最省事）**：

1. 打开 `cloudfunctions/api/pay.local.json`（MCH_ID 已填好）
2. 把另外三项填进对应字段：
   - `MCH_SERIAL_NO`：商户平台 → 账户中心 → API安全 → 商户API证书「详情」里那串 32 位十六进制
   - `MCH_PRIVATE_KEY_FILE`：把证书压缩包里的 `apiclient_key.pem` **复制到** `cloudfunctions/api/` 目录，这里填文件名 `apiclient_key.pem`（比把 30 行私钥塞进 JSON 稳妥得多）。也可以改成 `MCH_PRIVATE_KEY` 直接贴整段 PEM 或 base64
   - `API_V3_KEY`：你设的那个 32 位密钥
3. 保存文件 → 双击 `tools/deploy-pay.bat`（内部就是调 CLI 部署，会自动带上这个文件）
4. 这个文件已在 `.gitignore` 里，**不会进 GitHub**

填的都不对时，`createPayment` 的返回里 `missing` 会列出还缺哪个，照着补。

### 3. 验证（三步，缺一步都不算通）

1. 云函数云端测试跑 `{"action":"createPayment","orderId":"<某个待付款订单>"}`
   - 返回 `"payReady": false` + `missing` 列表 → 环境变量没填全，按列表补
   - 返回 `payParams`（含 `paySign`）→ 下单通了
2. 小程序里走一遍：结算 → 提交订单 → 点「微信支付」→ 手机弹出收银台 → 付 1 分钱
3. 付完看订单：状态应为「待发货」，`transactionId` 有值

### 4. 没开通时是什么表现

`createPayment` 返回 `{ok:false, payReady:false, missing:[...]}`，
支付页弹「在线支付还没开通，可以到店付款或微信转账给店长」，
店长台在「待付款」订单上有 **「标记收款」** 按钮兜底（`markPaid`，只有 admins 里的 openid 能点）。

### 5. 常见错

| 报错 | 原因 |
|---|---|
| `下单失败：签名错误` | 私钥贴错（贴成了证书 `apiclient_cert.pem`），或 `MCH_SERIAL_NO` 与私钥不配对 |
| `下单失败：AppID 与商户号不匹配` | AppID 没在商户平台关联，见本文前面的「AppID 账号管理」 |
| `下单失败：商户号未开通 JSAPI 支付` | 产品中心 → 我的产品 → JSAPI支付 → 开通 |
| `查单失败：ORDER_NOT_EXIST` | 传的 `out_trade_no` 和下单时不一致（本项目统一用订单号） |
| 付完订单还是「待付款」 | `confirmPay` 没调到：看小程序端网络与控制台日志 |
