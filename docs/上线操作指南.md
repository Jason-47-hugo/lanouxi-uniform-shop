# 上线操作指南（备案 / 隐私保护指引 / 微信支付商户号）

这份只讲**你要在哪个网站、点哪个位置、填什么**，不讲代码。代码那边已经就绪，
卡住的都是「必须有营业执照本人才能点」的环节。

三件事有先后：**备案 → 隐私保护指引 → 商户号**。备案没过，后面两件做了也发不出去。

---

## 一、小程序备案（ICP 备案）

**在哪做**：微信公众平台 <https://mp.weixin.qq.com> → 登录小程序账号 → 左侧「设置」→「基本设置」→ 往下找「小程序备案」→「去备案」。

**为什么要做**：2023 年 9 月起，国内小程序上线必须备案，不备案不能发布、不能搜索到、分享也受限。
备案是**管局**（广东省通信管理局）审，微信只是代收材料。

**要准备的材料**（都在妈妈那边）：

| 材料 | 说明 |
| --- | --- |
| 营业执照 | 珠海市香洲区兰欧茜服饰商铺（个体工商户），拍正本或副本，四角完整 |
| 经营者身份证 | 正反面，跟执照上的经营者是同一个人 |
| 手机号 + 邮箱 | 备案过程中管局会发验证码，手机号要能收短信 |
| 小程序服务内容 | 选「电商平台 / 自营电商」相关类目，描述写「校内校服款式展示与预订」 |
| 主体负责人 | **填妈妈**（广东要求是法定代表人/经营者本人） |
| 小程序负责人 | **填你**（广东允许不是法人，但要是小程序管理员） |

**流程与时间**：

1. 填表（约 20 分钟）→ 提交给微信初审（1–3 个工作日）
2. 微信初审通过 → 转广东省通信管理局（**法定 20 个工作日**，实际常见 1–2 周）
3. 期间管局可能打电话核实，**留的号码要接**
4. 通过后回到「基本设置」能看到备案号，填到小程序里（代码里不用改）

**常见被退回的原因**：

- 主体名称跟营业执照不完全一致（少「（个体工商户）」或多空格）——我们认证时就栽过这一次
- 服务内容描述太笼统，写「综合」会被要求细化
- 负责人手机号跟身份证归属地差异太大，会被要求补充说明

> 备案期间小程序**可以继续开发、可以用开发者工具、可以真机预览**，只是不能发布正式版。所以不影响我们现在做的事。

## 二、用户隐私保护指引

**在哪做**：微信公众平台 → 左侧「设置」→「服务内容声明」→「用户隐私保护指引」→「去完善」（有的版本在「设置 → 基本设置 → 用户隐私保护指引」）。

**为什么要做**：2023 年 9 月起，小程序**只要收集用户信息**就必须声明，否则调用 `wx.getUserProfile`、
`wx.chooseAddress`、`wx.chooseMedia` 这类接口会直接失败。

**这个小程序实际收集了什么**（照这个勾，别多勾）：

| 信息 | 用在哪 | 干什么 |
| --- | --- | --- |
| 收货地址（含姓名、手机号、地址） | 结算页「用微信里的地址」、地址簿 | 发货 |
| 相册 / 相机 | 店长台「换图」 | 店长拍商品实物图 |
| 订单信息 | 下单、我的订单 | 履约、售后 |

**不建议勾的**：位置信息、通讯录、微信运动、设备信息——我们一个都没用到，勾了要写更多说明，还容易被审核问。

**填的时候注意**：

- 「存储期限」写「订单完成后 3 年（售后追溯需要）」，别写「永久」
- 「是否提供给第三方」选「否」（货由店长发，数据不出腾讯云）
- 提交后要**重新提交代码审核**才生效，所以顺序是：先填隐私指引 → 再提审代码

## 三、微信支付商户号

**在哪做**：<https://pay.weixin.qq.com> → 「接入微信支付」→「成为商家」→ 用**营业执照**注册（不是用小程序账号注册）。

**要准备的材料**：

| 材料 | 说明 |
| --- | --- |
| 营业执照 | 同上 |
| 经营者身份证 | 正反面 |
| 结算银行卡 | **经营者本人**的借记卡（个体户不能绑别人的卡） |
| 门店照片 | 门头照 + 内景照各一张（校服店有实体店，拍店招就行） |
| 客服电话 | 能打通的 |

**费用**：开户免费，费率 **0.6%**（教育/校服类没有优惠费率），T+1 到账。

**拿到商户号之后还要做两件关联的事**：

1. 商户平台 →「产品中心」→「AppID 账号管理」→ 关联小程序 AppID `wx37e1073cc15df404` → 回小程序「微信支付」页确认授权
2. 商户平台 →「API 安全」→ 设置 **APIv3 密钥**（32 位）→ 下载**商户证书**（`apiclient_key.pem`）

> ⚠️ **这两个东西绝对不能写进代码仓库**。正确做法是放进云函数的环境变量：
> 开发者工具 → 云开发控制台 → 云函数 → `api` → 配置 → 环境变量，加
> `MCH_ID`、`MCH_KEY`（APIv3 密钥）、`MCH_SERIAL`（证书序列号）。
> 证书文件用「云函数 → 上传文件」放进去，读 `process.env` 或 `/tmp` 路径。

**代码那边我要改的**（等你有商户号）：把 `cloudfunctions/api/common/service.js` 里的
`pay` 从「演示直接置 paid」换成 `cloud.cloudPay.unifiedOrder(...)`，并新增一个
`payNotify` 的 HTTPS 触发路径校验签名。这部分**没有商户号没法测**，所以我没提前写。

## 四、数据库索引与集合权限（我可以做，已写进代码文档）

这部分不需要你去控制台一个个点，**照着 `docs/云开发接入指南.md` 的「数据库索引与集合权限」一节确认一遍**即可。
简要说结论：

| 集合 | 权限 | 为什么 |
| --- | --- | --- |
| `users` | 所有用户不可读写 | 只有云函数能碰；前端读自己要经过 `me` 云函数 |
| `products` | 所有用户不可读写 | 价格库存必须服务端给，开「所有人可读」等于把成本价给出去 |
| `orders` | 所有用户不可读写 | 同上，订单里有手机号地址 |
| `admins` | 所有用户不可读写 | 店长名单 |

索引（云开发控制台 → 数据库 → 选集合 → 索引管理 → 新建）：

| 集合 | 字段 | 类型 | 用途 |
| --- | --- | --- | --- |
| `orders` | `openid`（升序）+ `createdAt`（降序） | 组合 | 「我的订单」按人 + 时间倒序 |
| `orders` | `status`（升序）+ `createdAt`（降序） | 组合 | 店长台按状态筛选 |
| `orders` | `no` | 唯一 | 订单号查重，防止重复落单 |
| `products` | `sales`（降序） | 单字段 | 首页「本周精选」排序 |
| `users` | `openid` | 唯一 | 一人一条 |

> 数据量小的时候没索引也能跑，但单集合过 1000 条后 `listOrders` 会明显变慢，
> 而且云开发对没有索引的复杂查询有 3 秒超时。

## 顺序建议（一张表）

| 顺序 | 事情 | 谁做 | 卡多久 |
| --- | --- | --- | --- |
| 1 | 小程序备案 | 妈妈（你代填） | 1–3 周 |
| 2 | 隐私保护指引 | 你 | 10 分钟 + 随代码审核 |
| 3 | 上传体验版，真机走一遍 | 你 | 半小时 |
| 4 | 微信支付商户号 | 妈妈（你代填） | 1–3 个工作日 |
| 5 | 接 `requestPayment` + 回调 | 我 | 拿到商户号后 1 天 |
| 6 | 商品实拍图上云存储 | 店长拍 + 你传 | 半天 |
| 7 | 提审发布 | 你 | 1–7 天 |

第 3 步之前，我在代码里能做的都做完了；第 5、6 步要等外部条件。
