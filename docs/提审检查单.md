## 2. 功能页面与路径（审核员会点）

| 页面 | 路径 | 说明 |
|---|---|---|
| 首页 | 打开即到 | 按学校找 / 分类入口 / 本周精选 |
| 全部校服 | tabBar「分类」 | 30 款，可按学校、学段、品类筛 |
| 商品详情 | 首页点任一商品 | 颜色、尺码（150–200）、尺码参考面板、加入购物车 |
| 购物车 | tabBar「购物车」 | 改数量、删除、去结算 |
| 结算 | 购物车 → 去结算 | 收货地址（可调起微信地址）、快递/自提、积分抵扣、应付金额 |
| 支付 | 结算 → 提交订单 | 微信支付（未开通时会明确提示「到店付款」） |
| 我的订单 | tabBar「我的」→ 我的订单 | 五个状态分页，可确认收货/申请退货 |
| 我的 | tabBar「我的」 | 积分、地址簿、店长入口（仅店长可见） |
| 收货地址 | 我的 → 地址簿 | 增删改、设默认、从微信导入 |
| 店长台 | 我的 → 店长入口（仅 admins 里的 openid 可见） | 订单/商品/数据三标签 |

> **店长台这一页审核员看不到**（他的 openid 不在 admins 里），这正是设计意图。审核备注里可以写一句：
> 「店长台仅对店主本人微信号开放（按 openid 白名单），审核如需查看，可用测试账号 XXX 扫码，我们会临时加入白名单。」

## 4. 常见被退原因与本项目的对策

| 被退原因 | 本项目对照 |
|---|---|
| 涉及支付但未接入微信支付 | 已接 v3（`createPayment`/`confirmPay`），未开通时明确提示到店付款，不假装成功 |
| 类目与实际内容不符 | 商家自营 > 服饰内衣 / 鞋靴，与实际一致 |
| 缺少隐私协议或与实际收集不符 | 见 `docs/上线操作指南.md` 第二节，只勾三项 |
| 未完成备案 | 等备案号下来再提交 |
| 页面内容不完整/空白 | 13 页全部有内容，自测脚本覆盖 |
| 使用了测试数据当真实商品 | 已是 20 张店面实拍图 + 30 款商品；价格待店长核对，见 §5 |

## 5. 提审时可以主动说明的三件事

1. **数据**：云开发四集合（users/products/orders/admins），订单与积分存云端，断网自动退回本地演示数据。
2. **价格**：商品价格为店主提供，其中「麒麟断码长裤 38 元」是图上实价，其余为建议价，店主会在上架前核对。
3. **退款**：7 天无理由，退款按实付金额比例退，已抵扣积分同比例退回（`cloudfunctions/api/common/rules.js` 的 `refundPlan`）。

## 6. 提交后

1. 在「版本管理」里能看到「审核中」，一般 1–3 天（第一次提交可能 1–7 天）
2. 审核通过 → 点「发布」→ 全量发布
3. 发布后到「设置 → 基本设置」确认「服务类目」和「备案号」都已展示
4. 把版本号和通过时间补进 `docs/交接卡-20261117.md` 的 §1 现状
