## 2. 项目是什么

## 6. 尺码推荐（v0.6 新增）

## 8. 已知坑（别重蹈）

1. **根目录那 10 个 `gd-*.html` / `gd-*.html.err` 是垃圾**：0 字节 HTML + headless Chrome 的 `net::ERR_FILE_NOT_FOUND`。**不影响运行**，确认后可删，但按用户要求**先别删**。
2. `preview/` 的一次性审图产物（`al-* / aud-* / rh-* / typo-* / dump-*`、`shots/`、`dom*/`、`edge-profile/`、各种 `crop-*.py`）**已于 2026-11-22 清掉**（140 个文件 + 4 个目录，10.4MB），只留 `build.js / web-build.js / web-runtime.js / flow-test.js / make-audit.js / itest-size.html / itest.html / web-size-view.html / wrap-route.js / audit-report.js / html/`。以后再出这类文件，随手清。
3. `preview/build.js` 曾经跑不起来：`seed()` 里调了早就删掉的 `store.markTransferred` / `confirmPayment`。改 `store.js` 的导出名，记得同步搜一遍 `preview/`。
4. `preview/web-build.js` 的 `moduleFiles` 是**白名单**：新增 `utils/*.js` 必须加进去，否则网页版对应页面白屏报 `missing module utils/xxx`（`utils/size.js`、`utils/api.js`、`utils/cloud.js` 都踩过）。flow-test 里已加一条扫产物的断言，漏加会红。
5. 用 PowerShell `Get-Content` 看中文文件会显示乱码（控制台按 GBK 解码 UTF-8），读文件一律加 `-Encoding UTF8`。
6. **PowerShell 写中文文件会加 BOM**（`Set-Content -Encoding UTF8` 在 Windows PowerShell 5 里带 BOM），项目里的 wxml/js 原本无 BOM；写完检查首字节（`239,187,191` 就是 BOM），用 `[System.IO.File]::WriteAllBytes($f, $b[3..])` 去掉。
7. **截屏只能用旧版 headless**：`msedge --headless`（不是 `--headless=new`）+ `--no-sandbox --allow-file-access-from-files`；输出文件名结果打在 stderr 的「N bytes written to file」里。
8. 这个目录**不是 git 仓库**，没有版本历史可回滚，改之前先复制一份（现有 `uniform-shop.backup-20261117-1217`、`uniform-shop.backup-20261117-1755`、`uniform-shop.backup-20261122-1950`）。
9. 中文输出到重定向 stdout 可能 `UnicodeEncodeError`（Python 脚本要注意）。
10. **开发工具编译缓存**：改完代码只 `close/open` 有时还跑旧 bundle，必须先 `cli.bat cache --clean all`（v1.0 因此误判「云端没生效」半小时）。
11. **云开发 `update` 是合并语义**：给 `null` 字段加子字段会报 `-502001 Cannot create field`，数组会按索引合并丢项。`cloudfunctions/api/common/wxdb.js` 已统一对对象/数组用 `db.command.set()` 整块替换，**别在 service 里绕过 wxdb 直接 update**。
12. **店长改商品参数必须摊平**：云函数 `updateProduct` 读的是扁平字段（`payload.price/stock/name/image/onSale` + `payload.id`），`api.js` 里已经 `Object.assign({}, patch, {id})`；表单传的是字符串，服务端已用 `Number()` 兜住。

## 9.6 v1.4 真实支付（2026-11-26）

- **新增 `cloudfunctions/api/common/wxpay.js`**：微信支付 v3 JSAPI。只用 Node 自带 `crypto` + `https`，不引依赖。
  - `configured()` / `missing()`：判断环境变量齐不齐（`MCH_ID`、`MCH_SERIAL_NO`、`MCH_PRIVATE_KEY`、`API_V3_KEY`，可选 `PAY_APPID`、`PAY_NOTIFY_URL`）
  - `jsapi()` 下单 → `{prepayId, payParams}`；`payParams()` 生成小程序端 `wx.requestPayment` 要的 `{timeStamp,nonceStr,package,signType,paySign}`
  - `query()` 主动查单 → `{tradeState,transactionId,amountFen}`；`decryptResource()` 用 AES-256-GCM 解回调
- **云函数新增四个 action**：`createPayment`（下单，金额一律服务端算 `Math.round(order.amount*100)`）、`confirmPay`（查单确认，`trade_state==='SUCCESS'` 且金额一致才置 paid）、`markPaid`（店长标记已收款，仅 admins）、`payNotifyV3`（回调兜底，等有公网地址再启用）。状态一律用 `cas(pending_pay→paid)` 抢，重复确认返回 `already:true`。
- **收银台改成真的**：`pages/pay/pay.js` 的 `pay()` → `api.createPayment()` → 有 `payParams` 就 `wx.requestPayment`，成功后调 `api.confirmPay()` 再跳订单详情；没配商户号时返回 `payReady:false`，页面提示「在线支付还没开通，可以先到店付款或转给店长」。
- **兜底**：`pages/admin/admin.wxml` 给「待付款」订单加了「标记收款」按钮（`doMarkPaid` → `api.markPaid`），到店付款/转账的单店长一点就变「待发货」。
- **密钥只在云函数环境变量里**，仓库里没有任何密钥、证书、私钥。填法见 `docs/云开发接入指南.md` 的「微信支付」章节。
- 自测：`flow-test` **ALL PASS 116**（新增 8 条：收银台调 `wx.requestPayment`、下单走云函数、页面没有「演示版不会真实扣款」、保留「到店付款」、`wxpay.configured()===false`、`missing()` 列出关键变量、`api.js` 暴露三个新方法）；`cloud-test` **ALL PASS 159**（新增 `[16] 真实支付` 27 条：金额篡改无效、越权、金额少一分拒绝、`NOTPAY` 不认、重复确认只改一次、店长标记收款、非店长不能标记）。
- 决策见 `docs/决策记录.md` **D017**：主路是「主动查单」，回调只做可选兜底（云开发默认没有公网地址）。
